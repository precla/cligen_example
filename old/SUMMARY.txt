================================================================================
                          WHAT IT DEMONSTRATES
================================================================================

CORE CONCEPT: Dynamic Interface Expansion
──────────────────────────────────────────

  User types:  ip <ENTER>
                  ↓
  Program calls: getifaddrs()
                  ↓
  OS returns:  lo, ens192, docker0 (YOUR ACTUAL INTERFACES)
                  ↓
  Displayed in nice formatted table with status and IP addresses

KEY INSIGHT:
- Interface list is NOT hardcoded
- Interfaces are queried AT RUNTIME from the OS
- Works on any system automatically
- Data is always current
- No recompilation needed if interfaces change

                          WHY THIS IS IMPORTANT

This example demonstrates the CORE CONCEPT that makes CLIgen powerful:

HARDCODED APPROACH (Bad):
  char *interfaces[] = {"eth0", "eth1", "docker0"};
  // Must recompile if you add wlan0

DYNAMIC APPROACH (This program):
  getifaddrs();  // Query OS at runtime
  // Automatically works everywhere, always current

CLIGEN APPROACH (Automates this):
  <iface:string interface()>  // Tell CLIgen to expand dynamically
  // CLIgen handles everything - parsing, validation, completion, help

This simple example helps you understand:
  ✓ Why dynamic expansion is important
  ✓ How to query data at runtime
  ✓ CLI design patterns

================================================================================
                          KEY FUNCTIONS
================================================================================

get_interfaces()
  Purpose: Query OS for network interfaces (THE DYNAMIC PART)
  How: Uses getifaddrs() system call
  Result: Returns array of interface info
  Called: Every time user enters 'ip'
  Dynamic: Data is fresh each time, not cached

display_interfaces()
  Purpose: Format and display interfaces in a nice table
  How: Prints ASCII art with borders and columns
  Result: Beautiful formatted output
  Called: After get_interfaces()

show_help()
  Purpose: Display available commands
  How: Simple printf statements
  Result: Help text shown to user
  Called: When user enters 'help'

main()
  Purpose: Main endless loop - the CLI itself
  How: 1. Print banner  2. Loop: read input, process command
  Result: Interactive CLI experience
  Pattern: Classic CLI design used everywhere
