================================================================================
              CLIgen Dynamic Expansion Flow Diagram
================================================================================

1. CLI SPECIFICATION (ifconfig_cli.cli)
   ────────────────────────────────────

   show interface <ifname:string interface()>
                                     ↑
                        Tell CLIgen to call interface()
                        when user presses TAB here


2. USER INTERACTION
   ────────────────

   User types:    show interface [TAB]
                                ↓
   CLIgen sees parameter needs expansion
                                ↓
   CLIgen calls:  expand_interface() callback
                                ↓
   Returns list:  ["lo", "ens192", "docker0"]
                                ↓
   User sees:
   ┌─────────────────────────────┐
   │ lo      (UP)                │
   │ ens192  (UP)                │
   │ docker0 (UP)                │
   └─────────────────────────────┘


3. EXPANSION CALLBACK EXECUTES (test_expand.c / ifconfig_cli.c)
   ──────────────────────────────────────────────────────────

   expand_interface() called
         ↓
   getifaddrs() ──→ Query Operating System
         ↓
   Returns all interfaces on system
         ↓
   Filter and format results
         ↓
   Add to commands vector:   ["lo", "ens192", "docker0"]
   Add to helptexts vector:  ["(UP)", "(UP)", "(UP)"]
         ↓
   Return to CLIgen
         ↓
   CLIgen displays in completion menu


4. USER SELECTS INTERFACE
   ──────────────────────

   User selects: ens192
         ↓
   CLIgen parses the command
   ──────────────────────
   Parsed variables:
   {
     "ifname": "ens192"
   }
         ↓
   CLIgen calls command handler: show_interface()
         ↓
   Handler receives parsed variables
   Handler can now:
   - Query interface info
   - Configure it
   - Display status
   - etc.


5. COMPARISON: STATIC vs DYNAMIC EXPANSION
   ────────────────────────────────────────

   STATIC (Hardcoded List):
   ──────────────────────
   CLI spec defines:
       interface (lo | ens192 | docker0)

   Problems:
   ✗ Must recompile when interfaces change
   ✗ Only works on specific machines
   ✗ Can't handle dynamic scenarios


   DYNAMIC (Callback Function):
   ──────────────────────────
   CLI spec calls:
       interface <ifname:string interface()>

   Advantages:
   ✓ Discovers interfaces at runtime
   ✓ Works on any machine
   ✓ Handles hot-plugged devices
   ✓ Can be context-aware


6. EXECUTION TIMELINE
   ──────────────────

   Time    Event
   ────    ─────────────────────────────────────────
   T0      CLI starts
           Loads ifconfig_cli.cli
           Registers expand_interface callback

   T1      User types: show interface <TAB>

   T2      CLIgen invokes expand_interface()
           expand_interface calls getifaddrs()
           Result: lo, ens192, docker0

   T3      CLIgen displays completion menu
           User presses: e[TAB] → autocompletes to ens192

   T4      User presses [ENTER]
           Command: "show interface ens192"

   T5      CLIgen parses and validates
           Calls show_interface(ifname="ens192")

   T6      show_interface queries interface info
           Displays results to user

   T7      CLI returns to prompt


7. KEY CALLBACK PARAMETERS
   ──────────────────────

   expand_interface(
       h,              // CLIgen handle - context
       fn_str,         // Function name: "interface"
       cvv,            // Already-parsed variables (for context)
       argv,           // Function arguments from CLI spec
       commands,       // OUTPUT: options to show
       helptexts       // OUTPUT: help for each option
   )

   Example output:
   ────────────────
   commands[0] = "lo"
   commands[1] = "ens192"
   commands[2] = "docker0"

   helptexts[0] = "lo (UP)"
   helptexts[1] = "ens192 (UP)"
   helptexts[2] = "docker0 (UP)"


8. PRACTICAL EXAMPLE: EXPAND FROM DATABASE
   ─────────────────────────────────────────

   int expand_users(cligen_handle h, ..., cvec *commands, cvec *helptexts) {
       sqlite3 *db;
       sqlite3_stmt *stmt;

       sqlite3_open("users.db", &db);
       sqlite3_prepare_v2(db, "SELECT username FROM users", -1, &stmt, NULL);

       while (sqlite3_step(stmt) == SQLITE_ROW) {
           const char *user = (const char*)sqlite3_column_text(stmt, 0);
           cvec_add_string(commands, NULL, user);
           cvec_add_string(helptexts, NULL, "Database user");
       }

       sqlite3_finalize(stmt);
       sqlite3_close(db);
       return 0;
   }

   CLI spec:
       user <username:string users()>

   Result:
       user [TAB] → shows all users from database dynamically


================================================================================
                   This is why CLIgen is powerful
================================================================================

Traditional CLI builder:
   • Hard-coded command lists
   • Must recompile to add commands
   • Difficult to handle dynamic content
   • Complex custom parsing

CLIgen with dynamic expansion:
   • Specify command syntax once
   • Plug in callbacks that return dynamic data
   • Zero recompilation for content changes
   • Built-in parsing, validation, completion
   • Professional CLI with minimal code
